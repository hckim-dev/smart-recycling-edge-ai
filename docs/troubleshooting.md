# 설계와 트러블슈팅

[문서 목록](README.md) · [시스템 구조](architecture.md) · [통신 명세](protocol-spec.md)

영상·제어·센서·통신의 경계에서 선택한 구현 방식을 정리합니다. 코드로 확인되는 동작과 과거 발표 기록을 구분하며, 측정 원본이 없는 개선율은 성과로 확정하지 않습니다.

## 영상 전송과 화면의 분리

**과제.** 초기 발표 기록에는 Jetson 화면을 X11로 전달할 때 영상 지연이 발생했다고 정리되어 있습니다. 추론 장치의 GUI 전달과 키오스크 표시를 분리하는 방향으로 구성했습니다.

**구현.**

- Jetson은 화면을 직접 그리지 않고 검출·검사·제어를 수행합니다.
- 캡처 스레드는 최신 프레임을 유지해 대기 프레임이 쌓이는 경로를 줄입니다.
- OpenCV로 JPEG를 만들고 같은 프레임의 JSON과 길이 헤더로 묶습니다.
- Qt는 부분 수신을 누적해 완성된 메시지 단위로 해석하고 렌더링합니다.
- TCP_NODELAY를 사용합니다. 송신에는 `sendall`과 timeout이 있어 전송 대기가 메인 루프에 영향을 줄 수 있습니다.

[카메라](../edge_jetson/core/camera.py) · [송신](../edge_jetson/stream/socket_server.py) · [Qt 파서](../pc_dashboard/network/jetson_client.cpp)

**확인 범위.** 버퍼·패킷·처리 구조는 현재 코드에서 확인할 수 있습니다. 전체 경로의 Zero-Copy, 고정 60 FPS, 14.1ms 화면 지연은 코드 설정만으로 증명하지 않습니다. 발표자료의 수치는 당시 기록으로 남기고, 재측정 시 캡처 프레임 번호·단계별 시각·Qt 표시 시점·네트워크 조건을 함께 기록해야 합니다.

## 분류 통로의 선행 정렬

**과제.** 분류판 정렬과 도어 개방의 순서를 분리해, 통로 설정 전에 물체가 떨어지는 상황을 줄이는 것입니다.

**구현.** [recycle.c](../mcu_firmware/recycle.c)는 하단 두 축에 목표를 주고, `Servo_Is_Moving()`이 모두 false이면 상단 목표를 설정합니다. [servo.c](../mcu_firmware/servo.c)는 tick 차이와 120°/s 속도로 각도를 갱신합니다.

```text
품목 명령 → 하단 목표 설정 → 하단 램프 완료 → 상단 목표 설정
```

**확인 범위.** 램프 완료는 소프트웨어 판단입니다. 실제 모터 도착 피드백은 없습니다. 현재 닫힘은 상단·하단에 중립 이동을 함께 요청하므로 개방·닫힘 모두 한 축씩 움직인다고 설명하지 않습니다.

초기화에는 각도 설정 사이 지연 코드가 있지만, 전체 부팅 과정의 동시 구동·피크 전류 제거를 보장하지 않습니다. 전원 안정성은 실제 전류·전압·리셋 원인을 측정해 확인해야 합니다.

## 검출 누락에 대한 상태 보존

**과제.** 반사·흔들림으로 검출이 잠깐 끊길 때 매번 후보를 초기화하지 않고, 안정 조건을 만족한 뒤 개방하도록 구성합니다.

**구현.** [AutoDoorController](../edge_jetson/core/door_controller.py)는 유효 프레임·경과 시간을 함께 확인하고 최대 3회의 연속 누락 동안 후보를 보존합니다. 열린 뒤에는 최소 유지 시간과 부재 카운터·최대 시간을 적용합니다.

Qt도 짧은 누락에 표시 상태를 유지하지만, Qt의 확인 배너 카운터와 Jetson의 개방 조건은 별도입니다. 숫자를 고정 초로 환산하거나 두 FSM이 완전히 동기화된다고 표현하지 않습니다.

**확인 범위.** 동작은 같은 품목의 검출 결과를 기준으로 합니다. 개별 물체 추적 ID, 손 감지·끼임 감지 센서, 안전 인증을 구현한 것은 아닙니다.

## 초음파 적재율의 흔들림 처리

**과제.** 투입 중 센서 가림과 거리 변동이 적재율 표시를 흔들 수 있습니다.

**구현.** [bin_filter.c](../mcu_firmware/bin_filter.c)는 다음 순서로 처리합니다.

| 단계 | 기준 |
| --- | --- |
| 블랭킹 | 해당 품목 OPEN 명령 처리 후 2초 동안 이전 값 유지 |
| 이상치 배제 | 최근 5개 샘플의 중앙값 ±5cm 안에 있는 값의 평균 |
| 데드밴드 | 이전 적재율과 5%p 이상 차이가 나면 갱신 |
| 예외 | 유효하지 않은 거리·timeout은 이전 결과 유지 |

빈 통·만석 거리는 [main.c](../mcu_firmware/main.c)의 현재 보정값 38cm·8cm입니다. 샘플 취득은 약 2초마다 이루어집니다.

**확인 범위.** Echo 상승·유지 대기는 현재 10ms·30ms timeout을 사용합니다. 폴링 대기이므로 센서 상태가 메인 루프 지연에 영향을 줍니다. 2ms·4ms 또는 블로킹 85% 감소는 현재 구현의 결과로 사용하지 않습니다.

## UART 수신과 명령 경계

**과제.** 바이트 수신 ISR을 짧게 유지하고 명령 해석은 메인에서 수행합니다.

**구현.**

- [isr.c](../mcu_firmware/isr.c)는 USART2 SR을 읽은 뒤 DR을 읽고 바이트를 처리합니다.
- CR/LF에서 한 줄을 확정하고 메인에 준비 플래그를 넘깁니다.
- [main.c](../mcu_firmware/main.c)는 줄 안의 `$`부터 프로토콜 명령을 해석합니다.
- Jetson은 일반 진단 출력과 `$BIN`·`$DOOR_STATE`를 구분합니다.

**확인 범위.** 버퍼는 단일 메일박스입니다. 메인이 이전 줄을 처리 중이면 다음 바이트를 버립니다. 임의 노이즈 복구율·명령 전달률 100%를 보장하지 않으며 ACK·재전송은 후속 과제입니다.

## 시리얼 연결과 장치 점검

[SerialController](../edge_jetson/stream/serial_controller.py)는 포트 오픈 후 1초 대기·버퍼 초기화·RX 스레드 시작을 수행합니다. `dsrdtr=False`·`rtscts=False`는 흐름제어 설정이며, 이것만으로 모든 보드의 DTR 토글·리셋을 억제한다고 단정하지 않습니다.

연결 실패 시 점검 순서는 다음과 같습니다.

1. 대상 포트 경로와 장치 연결 상태를 확인합니다.
2. 장치 소유 그룹과 실행 계정의 접근 권한을 확인합니다.
3. baudrate·배선·전원·MCU 부팅 로그를 확인합니다.
4. Jetson이 실제 연결 또는 SIMULATE 중 어느 모드인지 확인합니다.

```bash
ls -l /dev/ttyACM0
id -nG
```

대상 Ubuntu 장치가 dialout 그룹을 사용한다면 계정을 그 그룹에 추가하고 새 로그인 세션에서 권한을 확인할 수 있습니다.

```bash
sudo usermod -aG dialout "$USER"
```

장치 경로 고정이 필요하면 실제 장치 식별자를 기준으로 udev 규칙을 구성합니다. 모든 ttyACM 장치에 전역 쓰기 권한을 부여하는 설정을 기본 실행 절차로 요구하지 않습니다.

## 검증 기록의 기준

- 소스에서 확인한 설정과 실제 장치 측정값을 구분합니다.
- 재현 절차, 입력·장치·버전, 관찰 결과, 남은 한계를 함께 기록합니다.
- 전압·전류·FPS·지연·복구율은 원본 계측 자료와 조건이 있을 때 수치로 보고합니다.
- 단위 테스트·서버 연동 확인·타깃 추론·기구 동작을 서로 다른 검증 단계로 다룹니다.

원본 [발표자료](presentation/smart_recycling_final_report.pdf)는 별도로 보존합니다. 현재 구현·메시지 규약은 코드와 이 문서 묶음을 기준으로 합니다.
